# 對話摘要 — 2026-10-09

這份是**一整天對話的過程摘要**：從聊這台掌機，到 SDR 做到 M3。
技術細節與實測數字在 [DEVLOG.md](DEVLOG.md)，設計在 [DESIGN.md](DESIGN.md)；
這裡記的是「怎麼一路走過來的」——提了什麼、決定了什麼、哪裡修正過方向。

---

## 1. 認識平台（總綱 repo）

- 使用者介紹了 RP2040 掌機與總綱 repo `rp2040-retro-handheld`：一塊硬體、多支韌體
  （Doom、NES、Apple II、MakeCode、鍵盤、注音終端機、載入器、電子字典）。
- 讀了 `docs/HARDWARE.md` 與 `docs/ICON-STYLE.md`，提出幾點：LoRa UART 可固定在
  GPIO 0/1、GPIO 29 可量電池、ICON-STYLE 封面數量寫錯、`retro-editor` 只有 11 色違反
  自己的規則、檢查清單的腳本是空的。
- 使用者要求修 ICON-STYLE：改封面數量、補上 RAW → PNG 並排比較腳本、把
  `retro-editor` 列進已知偏離。commit 並 push 到總綱 repo。

## 2. 決定做 SDR，找路線

- 上網查 RP2040 做 SDR 的三種做法：Tayloe 混頻（Pi Pico Rx）、直接取樣
  （PiccoloSDR）、QSD/QSE 收發機（uSDR-pico）。
- 使用者問「能不能不加硬體」→ 走**直接取樣**，只收 0–250 kHz（LF）。
- **第一個修正**：「只接一根天線就好」不成立。ADC 需要偏壓、GPIO 27 是 74HC165
  的推挽輸出不能用、GPIO 26 是鍵盤 CLOCK。最後設計成 **GPIO 26 分時**：加 3 顆零件。
- **第二個修正**：偏壓原本設計在中點 1.65 V，發現那正好是 74HC 的切換門檻，改成
  **0.41 V**。
- 使用者問能不能出聲、畫面能顯示多少 → 規劃喇叭解調與 320×240 版面。
- 寫設計文件，開新 repo `rp2040-retro-sdr`（public），push。

## 3. M1：頻譜與瀑布圖

- 照 retro-dict 的分層：`firmware/` 純 C（PC 可測）＋ `RetroSDR/` Arduino sketch。
  沿用 retro-dict 的 `keys.c`、`TFT_DMA`、偏移編譯腳本。
- 查 PicoApple2 的掃描程式，確認 LATCH 是 595 與 165 共用；鍵盤矩陣已沒有方向鍵。
- PC 測試抓到兩個 FFT 精度問題（量不到雜訊、截斷造成假訊號）並修正。
- **工具鏈**：這台電腦沒有。使用者說「其他專案應該知道」——查證後確認其他專案
  是在編譯當下才找工具鏈，這台從沒編過。安裝 Arduino IDE 2.3.10 ＋ arduino-pico
  5.6.1，arduino-cli 加進 PATH。第一次編譯就成功。
- **燒錄**：用 USB 直接燒會蓋掉 loader，使用者選擇做 standalone 版（從 bundle
  Release 取 trampoline 合併）。
- **上機**：畫面出來了，但每塊 139 ms（預算 65 ms），全部掉塊。使用者發現沒聲音
  ——M1 本來就沒做音訊，這點燒錄前沒先講清楚。

## 4. 把 M1 調到不掉塊

- 超頻 250 MHz、加逐段計時。
- 發現 **arduino-pico 的 SPI 實際只有 24 MHz**（clk_peri 接在 48 MHz USB PLL）。
  改接系統時脈後畫面 61 → 23 ms。
- 使用者指出自己的 LCD 跑得到 40 MHz → 確認那是 pico-sdk 的 infones，pico-sdk
  不受影響；修正筆記裡的說法。
- 改用實數 FFT（2048 點複數＋拆分），每塊 60 ms，**不再掉塊**。
- 使用者要求把開發過程做成筆記 → 開始寫 `DEVLOG.md`。
- 使用者提議用瀑布圖當 icon → 建議「畫一台螢幕上有瀑布圖的收音機」以符合
  ICON-STYLE，使用者同意，排到 M5。

## 5. M2：喇叭出聲

- Core 1 跑 DDC（NCO、CIC、FIR、AM/CW/USB/LSB、AGC），GPIO 7 PWM 500 kHz。
- 使用者把側邊欄的工作階段從 USER 搬到這個專案資料夾，記憶也一併複製過去。
- **上機問題**：有雜訊聲、音量可調，但有**噠噠聲**。原因是 DDC 沒丟掉偏壓暫態、
  也沒補償鍵盤掃描空檔的相位。修好後使用者確認噠噠聲消失。

## 6. Core 1 優化

- 先量再改：瓶頸是 FIR 的 64 位元乘法。對稱摺疊＋拆成 32 位元乘法，結果逐位元相同。
- CIC 拆兩級，只從 18 → 14 ms（預估 6 ms），原因是暫存器不夠用。總計 55 → 28 ms。
- 使用者問改用 pico-sdk 會不會有幫助 → 評估後建議現在不換，等 RAM 吃緊再說。

## 7. 焊上偏壓網路，實測

- 使用者問「GPIO 26 到底是天線還是鍵盤」→ 解釋分時與電壓範圍錯開的原理。
  確認除了 GPIO 0/1 之外沒有空腳，ADC 腳全被佔用。
- 加 GPIO 0 測試訊號（`T`）。沒焊之前耦合不進去。
- 使用者焊好 330k/47k/1nF 與天線：**鍵盤正常**，雜訊底線上升（天線有作用），
  測試訊號 S/N 約 10 dB，喇叭聽得到嗶聲。
- 40 kHz 上有忽強忽弱的訊號，推測可能是 JJY。

## 8. 意外發現：中波廣播

- 使用者：**拔掉 USB 能依稀聽到廣播**，插上 S/N 變差；拔掉筆電充電器聲音又回來。
- 判讀：中波 AM 電台**混疊**進來（ADC 前沒有抗混疊濾波器）。早先「欠取樣收不到
  能聽的東西」的判斷**是錯的**。也意味 40 kHz 的訊號不一定是 JJY。
- 使用者決定把「**中波模式**」記下來，先不做。

## 9. M3：JJY 解碼

- 使用者問 JJY 是什麼 → 解釋授時台、電波錶、每秒一位元的編碼。
- 查 NICT 官方格式後寫解碼器，PC 上三層測試（格式、雜訊包絡、40 kHz 端到端）都過，
  接上板子，畫面顯示解碼狀態。
- 使用者判斷 **40 kHz 附近有大訊號會蓋台**，實測延後，記進筆記。

## 10. 統計頁與收尾

- 做了統計頁（`I`）：不插 USB 時也能在螢幕上看數字。順帶量到充電器讓雜訊底線
  高約 9 dB。
- 計劃書加一條：**繪製本系統的方塊圖**。
- 整理這份對話摘要。

## 我在過程中修正過的判斷

| 原本說的 | 後來發現 |
| :--- | :--- |
| 只接一根天線就能收 | 至少要 3 顆零件做偏壓與耦合 |
| 偏壓放中點 1.65 V | 那是 74HC 的門檻，改 0.41 V |
| arduino-pico 預設 133 MHz | 實際約 200 MHz |
| PicoApple2 很可能也只有 24 MHz SPI | 只是推測；pico-sdk 專案不受影響 |
| CIC 拆兩級可降到 6 ms | 實際 14 ms，暫存器不夠用 |
| 欠取樣收中波不建議、收不到 | 實際聽得到人聲與音樂 |
| 40 kHz 的訊號可能是 JJY | 也可能是中波混疊或本地干擾，未確認 |
