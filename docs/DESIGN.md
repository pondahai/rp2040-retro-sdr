## 0. 目標與非目標

**目標**

- 不改主板，只在 GPIO 26 外加 3 顆被動元件就能收訊
- 鍵盤矩陣照常可用（數字鍵輸入頻率）
- 喇叭出聲：AM／USB／LSB／CW 解調
- LCD 盡可能顯示：頻譜、瀑布圖、S 表、解碼結果
- 連結到 `0x10004000`，從載入器選單啟動

**非目標**

- 收人聲廣播：250 kHz 以下在台灣基本上沒有。那是之後 Tayloe 子板的事（見 §9）
- 發射
- 透過 USB 把樣本串流到電腦

### 預期聽得到什麼

| 訊號 | 頻率 | 模式 | 聽起來 |
| :--- | :--- | :--- | :--- |
| BPC（中國商丘） | 68.5 kHz | CW | 每秒一次、長短不一的嗶聲 |
| JJY（日本） | 40 / 60 kHz | CW | 同上 |
| 海軍 VLF 台 | 15–30 kHz | — | MSK 數據，聽起來像嘶嘶聲 |
| 閃電 sferics | 3–10 kHz | AM 寬頻 | 劈啪聲，夏季傍晚多 |

收不收得到，取決於天線長度、時段和室內雜訊，**要實測**。M1 的目的就是先量雜訊底線。

## 1. 硬體

### 1.1 天線輸入網路（唯一的外加零件）

```
3V3 ──[330k]──┬──[47k]── GND        偏壓 ≈ 0.41 V
              │
天線 ──||──────┴── GPIO 26（ADC0 ／ 74HC CLOCK）
      1nF
```

| 參數 | 值 | 理由 |
| :--- | :--- | :--- |
| 偏壓 | ≈ 0.41 V | 低於 74HC 在 3.3 V 時的 V<sub>IL</sub>（約 1.0 V），CLOCK 在取樣期間穩定在 LOW |
| 戴維寧等效 | ≈ 41 kΩ | 分壓電流約 9 µA；ADC 取樣電容的穩定時間遠小於 2 µs |
| 高通轉角 | ≈ 3.9 kHz | 1 nF × 41 kΩ；60 Hz 交流聲衰減約 36 dB，避免長天線把 CLOCK 拉過門檻 |
| 天線 | 3–10 m 電線 | 越長越好；室外優於室內 |

**為什麼不偏壓在中點 1.65 V？** 1.65 V 正好在 74HC 的切換門檻附近，595／165 會亂移位、
產生穿透電流，並把數位雜訊灌回訊號。天線訊號只有 µV–mV 等級，0.41 V 的餘裕綽綽有餘。

**為什麼不用 GPIO 27？** 它接 74HC165 的 QH，是一直在推動的推挽輸出。

### 1.2 對鍵盤掃描的影響

- GPIO 推 CLOCK 時，分壓電阻的負載可以忽略
- 天線加 1 nF 電容會讓邊緣變慢約 1 µs → **掃描時脈壓在 200 kHz 以下**
  （M1 實作：每半週期 2 µs，約 125 kHz；CLOCK 驅動能力開到 12 mA）
- 掃描期間 CLOCK 的邊緣會從天線輻射出去；這段時間不取樣，所以不影響頻譜

### 1.3 已知的自我干擾

| 來源 | 頻率 | 處理 |
| :--- | :--- | :--- |
| 音訊 PWM 載波 | 500 kHz | 與取樣率相同 → 摺疊到 DC，被濾掉（§4.3） |
| PAM8403 開關頻率 | 約 250–300 kHz | 摺疊成一根固定的尖峰；實測後在頻譜上標為已知雜訊 |
| ILI9341 SPI | 62.5 MHz 一帶 | 遠超頻寬；只要不和取樣邊緣同步，就只會抬高雜訊底線 |
| 開關電源／充電電路 | 依實機 | M1 實測後列表 |

## 2. 系統架構

### 2.1 核心分工

| | 工作 |
| :--- | :--- |
| **Core 0** | ADC DMA、寬頻 FFT、UI 與 LCD 繪製、鍵盤掃描、SD 卡 |
| **Core 1** | DDC 串流、解調、授時碼解碼、音訊 PWM 餵料 |

Core 0 和 Core 1 之間用兩個單向環形緩衝交換資料：ADC 樣本給 Core 1，窄頻 FFT 結果與解碼狀態給 Core 0。

### 2.2 時脈

| 時脈 | 來源 | 值 |
| :--- | :--- | :--- |
| clk_sys | PLL_SYS | 125 MHz（不夠再超頻到 250 MHz，見 §8） |
| clk_adc | PLL_USB | 48 MHz → ÷96 = **500 ksps** |
| 音訊 PWM | clk_sys | ÷ wrap 250 = **500 kHz** |

兩個 PLL 都來自同一顆 12 MHz 石英，所以 ADC 取樣率和 PWM 頻率是**整數比鎖死的**。這是 §4.3 的前提；改 clk_sys 時，PWM 的 wrap 要跟著重算。

### 2.3 分時：ADC 取樣與鍵盤掃描輪流用 GPIO 26

```
|── ADC 取樣一塊 ──|掃描 ~0.7ms|── ADC 取樣一塊 ──|掃描|…
```

1. ADC 以 DMA 雙緩衝抓一整塊（N<sub>blk</sub> = 32768 點，65.5 ms）
2. 塊與塊之間：停 ADC → GPIO 26 切回 SIO 輸出 → 掃一次 8×8 矩陣（8 列 × 24 時脈，放慢後約 1 ms）→ 切回 ADC
3. 取樣期間 **LATCH（GPIO 14）保持不動**（停在高），595 的輸出凍結，鍵盤 LED 不會閃。
   LATCH 已確認是 595 的 RCLK 與 165 的 SH/LD 共用：PicoApple2 的 `scan_matrix()` 先拉高鎖存 595，
   再拉低 1 µs 讓 165 載入

| 影響 | 數值 | 評估 |
| :--- | :--- | :--- |
| 樣本損失 | 約 1.5% | 對寬頻 FFT 無影響；對每秒一個符號的授時碼無害 |
| 按鍵延遲 | 約 66 ms | 可接受 |
| 去彈跳 | `keys.c` 原封不動 | 30 ms 的門檻在 65 ms 的掃描週期下，本來就等於「連續兩次一致」 |

窄頻 DDC 在空隙處補零。1 ms 的空隙在 8 kHz 的音訊裡約 6 個樣本，CW 嗶聲中會有輕微的喀聲。若太明顯，就改成在空隙處做線性內插。

## 3. 寬頻模式：0–250 kHz 全景

- 每塊取前 4096 點，套 Hann 窗後做**實數 FFT**（q15 定點運算，M0+ 沒有 FPU）
- bin 寬 = 500k / 4096 ≈ **122 Hz**，2048 個 bin → 每個像素合併 6–7 個 bin 取最大值
- 指數平均（α 可調）降低雜訊；另外做峰值保持
- 輸出：320 點的 dB 值 → 頻譜曲線＋一列瀑布圖

---

## 4. 窄頻模式：DDC、解調、音訊

### 4.1 訊號鏈

```
ADC 500k ─→ NCO 混頻 ─→ CIC ÷62.5* ─→ FIR 補償/通道濾波 ─→ 8 kHz I/Q ─┬→ 解調 → 音訊
 (int16)    (查表 sin/cos)                                            └→ 窄頻 FFT（顯示用）
```

\* 實際以 CIC ÷125 到 4 kHz，或 ÷50 到 10 kHz 加 FIR ÷1.25，實作時選一種。這裡的重點是基頻落在 4–10 kHz。

- **NCO**：32 位元相位累加器，1024 點 sin 查表，頻率解析度 500k / 2³² ≈ 0.0001 Hz
- **CIC**：3 階，int32 累加
- **運算預算**：每個樣本約 40 個週期 × 500 k = 2000 萬週期/秒，占 Core 1 在 125 MHz 下的 16%

### 4.2 解調

| 模式 | 做法 | 通帶預設 |
| :--- | :--- | :--- |
| AM | √(I² + Q²)，去 DC | ±3 kHz |
| USB / LSB | 以 Weaver 或 Hilbert 取單邊帶 | 2.4 kHz |
| CW | 調諧點偏移 800 Hz 後取實部 → 800 Hz 嗶聲 | 200 Hz（可調 50–500 Hz） |

AGC 用峰值追蹤，attack 快、decay 慢（約 0.5 s），避免授時台的振幅調變把音量拉得忽大忽小。

### 4.3 音訊輸出（GPIO 7 → PAM8403）

- PWM 頻率 = **500 kHz，與 ADC 同步** → PWM 載波經 500 ksps 取樣後摺疊到 0 Hz，被 DDC 和寬頻 FFT 的去 DC 處理掉
- wrap 250 → 解析度約 8 位元；對嗶聲和劈啪聲足夠
- 8 kHz 音訊以零階保持升頻，由 Core 1 用計時器中斷餵 PWM duty
- RC 低通沿用主板現有的設計

## 5. 授時碼解碼

BPC 和 JJY 都是**每秒一個符號、以載波功率變化編碼**：

| | 編碼 | 一幀 |
| :--- | :--- | :--- |
| JJY | 載波 100% 持續 0.8／0.5／0.2 s → 0／1／標記 | 60 s |
| BPC | 載波降低 0.1／0.2／0.3／0.4 s → 2 位元一個符號，另有幀首 | 20 s |

流程：

1. 窄頻 I/Q → 功率包絡 → 抽取到 100 Hz
2. 自適應門檻（最近 10 s 的高低百分位數之間）→ 二值化
3. 找每秒的下降邊緣 → 量脈寬 → 分類符號
4. 幀同步 → 檢查同位位元 → 輸出日期時間
5. 連續兩幀一致才算「鎖定」

**注意**：BPC 的完整格式要以官方規格為準，實作前要再查證。上表只是用來估算工作量。

## 6. 輸入

- 直接沿用 `rp2040-retro-dict/firmware/keys.c`：輸入 8 byte 的 bit mask，輸出按鍵事件
- 去彈跳不用改：`keys.c` 要求狀態穩定 30 ms，在約 66 ms 的掃描週期下就是「連續兩次一致」，按鍵延遲約 130 ms
- 連發：400 ms 起跳，間隔實際上被掃描週期限制在約 66 ms
- **鍵盤矩陣上已經沒有方向鍵**（rp2040-retro-dict 記載），方向一律走 D-pad

下表是做完 M2 之後的完整配置；M1 實際的按鍵見 README。

| 按鍵 | 功能 |
| :--- | :--- |
| `0`–`9`、`.`、Enter | 輸入頻率（kHz） |
| ← → | 調頻率（步進依縮放而定） |
| ↑ ↓ | 縮放／步進 |
| `W` | 寬頻／窄頻 |
| `M` | 解調模式循環 |
| `B` | 通帶寬度 |
| `+` `-` | 音量 |
| `R` | 錄音開始／停止 |
| `P` | 預設清單 |
| `Esc` | 回到上一層／靜音 |

## 7. 顯示（ILI9341 320×240 橫向）

```
┌────────────────────────────────────────┐
│ 68.500kHz  CW  BW 200Hz   S:▮▮▮▮▯▯ -42dB │ y 0–15    狀態列
├────────────────────────────────────────┤
│     頻譜曲線（平均＋峰值保持）           │ y 16–95   頻譜（80 px）
│   ░░░▓▓█▓░░  ┊通帶陰影┊  ↓調諧游標       │
├────────────────────────────────────────┤
│                                        │
│          瀑布圖                        │ y 96–191  瀑布圖（96 px）
│                                        │
├────────────────────────────────────────┤
│ BPC ▮▮▯▮▯▯▮… 2026-10-09 21:34:07 鎖定 ✓  │ y 192–223 解碼列／音訊波形
├────────────────────────────────────────┤
│ [W]寬/窄 [M]模式 [0-9]頻率 [R]錄 [B]頻寬  │ y 224–239 按鍵提示
└────────────────────────────────────────┘
```

- **頻譜**：寬頻時是 0–250 kHz；窄頻時是調諧點 ±（通帶 × 2.5）。通帶用半透明陰影標出，已知雜訊（§1.3）用小三角標記
- **瀑布圖**：RAM 裡存 320×96 的 8 位元調色盤索引環形緩衝（30 KB），每幀以 SPI DMA 重畫
  - 不用 ILI9341 硬體捲動：它只沿長軸捲，橫向畫面下瀑布圖會變成左右流動
  - 調色盤：黑 → 藍 → 青 → 黃 → 紅 → 白，256 階預先轉成 RGB565
- **解碼列**：鎖定時顯示最近 60 個符號＋日期時間；未解碼時顯示即時音訊波形
- **S 表**：通帶內功率與通帶外雜訊底線，差值即 SNR
- **更新率**：寬頻約每 66 ms 一列（跟著取樣塊）；窄頻約 10 列/秒

## 8. 資源預算

### 記憶體（264 KB SRAM）

| 項目 | 大小 |
| :--- | ---: |
| ADC 雙緩衝 2 × 32768 × int16 | 128 KB |
| 瀑布圖環形緩衝 | 30 KB |
| FFT 工作區＋窗函數＋調色盤 | 約 20 KB |
| DDC／解調／音訊緩衝 | 約 8 KB |
| FatFs＋SD | 約 4 KB |
| 堆疊、其他 | 約 16 KB |
| **合計** | **約 206 KB** |

若太緊，第一個可以砍的是 ADC 緩衝：改成 2 × 16384，按鍵延遲降到約 33 ms，樣本損失升到約 2%。

### CPU（125 MHz）

| | 估計 |
| :--- | :--- |
| Core 1：DDC＋解調＋音訊 | 約 25% |
| Core 0：4096 點 q15 FFT ×15/s | 約 30%（需實測） |
| Core 0：LCD 重畫 30 KB × 15/s | DMA 為主，CPU 約 10% |

不夠時依序：降瀑布圖更新率 → 超頻到 250 MHz（同時把 PWM wrap 改成 500，維持 500 kHz）。

## 10. 里程碑

| | 內容 | 完成的判準 |
| :--- | :--- | :--- |
| **M1** | ADC 取樣、寬頻 FFT、頻譜＋瀑布圖、鍵盤分時 | 能看到實機雜訊底線；按鍵正常；鍵盤 LED 不閃 |
| **M2** | 窄頻 DDC、CW／AM 解調、喇叭出聲 | 用訊號產生器或 PIO 自發 68.5 kHz 測試音，喇叭聽得到 |
| **M3** | BPC／JJY 解碼 | 收到真實訊號並連續兩幀一致 |
| **M4** | SD 卡錄音（`.wav`）、預設清單 | 錄下的檔案能在電腦上用 SDR 軟體開啟 |
| **M5** | 封面（依 `ICON-STYLE.md`）、連結到 `0x10004000`、收進 bundle | 從載入器選單啟動 |

M2 的測試訊號可以由掌機自己產生：用另一支 PIO 在閒置的 GPIO 0 輸出 68.5 kHz 方波，旁邊繞一圈線當作「發射天線」。不必有外部儀器就能驗證整條訊號鏈。
